# 面试官类型（cn）

> 来自单一职能、单一行业的小样本归纳。**这是种子，不是全集。** 模块 B 判定时宁可"未分类"，不可硬套。
> 字段固定：识别特征 / 他怕买错什么 / 追问链路 / 应答范式 / 禁忌 / 通过信号。只描述面试官行为，不评价面试官。
> 标 † 的字段不是直接观察，是由同条目其他字段反推的，命中从零积累；"待积累"表示样本里没有观察到。
> 类型编号沿用原始归纳顺序，不代表出现频率。新类型请走 `templates/zh/contribute-type.md`。
> 八个类型全部来自社招观察。校招特有的面试官类型（如按固定题本逐题问、几乎不追问的结构化面试官，批量筛选的 HR）本库尚无条目，**需要持续录入样本**，按贡献与反馈程度迭代；遇到时按"未分类"输出并描述可观察特征。

## 类型 A · 框架型 / 0→1 开荒型

- **识别特征**：开放式问题；主动说"行业匹配不重要"；后段主动交底业务现状。
- **他怕买错什么**：只会跑旧行业固定套路、不能独立开荒的人。
- **追问链路**：开放题 → 看框架 → 追一格具体做法 → 验证和止损意识 → 交底，看你接不接得住。
- **应答范式**：框架先行 → 每层塞数字 → 验证路径和切换条件（骨架 A）→ 反向提问接他交底的问题。
- **禁忌**：只给框架不给数；给结论不给反悔条件。
- **通过信号**：主动交底真实业务现状。

## 类型 A-2 · 现场案例题型（A 的变体）

- **识别特征**：业务负责人亲自面；先问经历，中段抛一道"如果是你，在我们的约束下怎么做 X"的案例题；对你的方案不打断，全程听完；后段主动交底真实现状（如流量构成、什么不能做）；结尾告诉你"进来后要补什么"。
- **他怕买错什么**：只会讲自己行业、进来后不能在新约束下重新搭方案的人；在强监管行业里会绕红线的人。
- **追问链路**：经历 → 追一个取舍逻辑（"核心做哪几个、怎么判断取舍"）→ 追行业约束 / 监管理解 → 案例题 → 追简历上与他业务相关的项目 → 离职动机 → 隐性用户题（"你自己用 / 买吗"）→ 反向提问 → base 地。
- **应答范式**：骨架 H 先行（先问现状与禁区，再问画像）→ 分路线框架，每条路线 ≤ 90 秒 → 主动把红线写进方案（"这条在监管下不能做，所以我会……"）→ 3 分钟内收口 → 隐性用户题用骨架 J → 反向提问接他的交底。
- **禁忌**：在强监管行业提任何"不直接提品牌""换个形式"类的绕行方案；答方案前不问现状；用不熟行业的产品做类比（行业语言差在类比里最容易暴露）。
- **通过信号**：结尾给"进来后要补什么"的清单（已经在按入职考虑）；追简历上的项目（在找加分项而不是找减分项）。

## 类型 B · 数据拆解型

- **识别特征**：问题短、节奏快、追口径、对故事无反应、对数字有反应。
- **他怕买错什么** †：用故事代替数、口径经不起追的人。
- **追问链路** †：要数 → 追口径与折算 → 追归因 → 追成本结构与上限。
- **应答范式**：数字先行 → 主动报口径和折算率 → 归因用骨架 B → 不知道的说"估计值，误差范围 X"。
- **禁忌**：反问确认；代理指标冒充归因；"效果很好"代替数。
- **通过信号**：待积累。

## 类型 C · 专业深度型

- **识别特征**：案例题加约束、追术语定义、测能力边界。
- **他怕买错什么** †：概念混用、边界不清、引用不可溯源的人。
- **追问链路** †：带约束的案例题 → 追术语定义 → 逐步加约束测边界。
- **应答范式**：复述全部约束 → 术语挂案例 → 到边界主动收口（骨架 E）→ 引用必须可溯源。
- **禁忌**：引用无法核实的外部数据；概念混用；答题漏约束。
- **通过信号**：待积累。

## 类型 D · HRBP 型

- **识别特征**：主导时间长；问动机 / 稳定性 / 期望；自述"业务深度评估不了"。
- **他怕买错什么** †：留不住、口径前后不一、定级谈不拢的人。
- **追问链路** †：动机 → 稳定性（离职原因、过往任期）→ 期望（薪资、到岗）→ 定级依据。
- **应答范式**：每个核心证据准备可搬运一句话（骨架 D）→ 复杂机制只给结果和量级 → 离职 / 到岗固定口径 → 薪酬杠杆只在此信道且对方先问。
- **禁忌**：把机制设计的精妙讲给 HR；口径漂移。
- **通过信号**：问 base 地 / 到岗时间。

## 类型 E · 验证型

> 样本最少的一类。只有"应答范式"是直接观察，其余全部为反推。

- **识别特征** †：面前已看过你的作品、笔试或材料；问题围绕"这个为什么这样做"；时长短。
- **他怕买错什么** †：作品不是本人做的。
- **追问链路** †：指认一处设计 → 问为什么 → 换一处再问。
- **应答范式**：让作品自己说话，你只补一句设计决策的"为什么"。
- **禁忌** †：为作品追加当时没有的理由；讲作品之外的经历。
- **通过信号**：待积累。

## 类型 F · 战略抽象型 / 参谋岗

- **识别特征**：问题多层抽象；要求跨平台 / 跨模式对比；追"怎么评估 / 怎么证伪"；对实操案例点头不追问；结尾给结构性反馈。
- **他怕买错什么** †：只有执行案例、没有评估与证伪方法的人。
- **追问链路** †：多层抽象题 → 要求对比 → 追评估指标 → 追证伪条件 → 结构性反馈。
- **应答范式**：逐层点数 → 框架先行 → 每维度给评估指标 + 证伪条件（骨架 F）→ 案例只填一格 → 换位题真站到对方位置。
- **禁忌** †：用一个实操案例硬撑抽象题；给判断不给评估设计。
- **通过信号**：待积累。反向信号见 `signals.md`：结尾给结构性反馈但不提岗位。
- **岗位错配提示**（模块 B-2 判定为 F 时强制引用）：类型 F 出现 = 参谋型岗位。候选人的能力区间若在执行 / 策略 / 机制层，一面就用反向提问（骨架 G）筛。

## 类型 G · 错配识别 / 转推型

- **识别特征**：按时间阶段逐段问经历（"刚加入负责哪块""后来呢""对什么目标负责"），在还原你真正的能力区间；中途给出总体评价；随后直接说"这个岗位有能力错配"，并转推其他岗位；主动介绍公司架构给你选。
- **他怕买错什么**：不怕买错人，怕把对的人放错岗。他是在替公司做人才分配，不是在替这个岗位守门。
- **追问链路**：逐段还原经历 → 问汇报关系和实际权限（"X 的人向你汇报吗""Y 在你这边吗"）→ 判定错配 → 问你想往哪走 → 转推。
- **应答范式**：汇报关系和权限**如实答**（这类面试官核实得很细，会交叉验证）；方向题用骨架 I 接他递的台阶；反向提问用骨架 G 问清转推岗位的架构（平行还是同一负责人、负责人是否亲自带）；结尾把他推荐的方向复述一遍，确认口径一致。
- **禁忌**：为了匹配当前岗位硬凑经验；方向题说"想做没做过的"；说出"舒适区"三个字（在面试官耳朵里等于"不想深耕"）。
- **通过信号**：对当前岗位 = 不通过信号（介绍架构给你选、问你想往哪走，见 `signals.md`）；对转推岗位 = 待积累。
- **岗位错配提示**（模块 B-2 判定为 G 时强制引用）：类型 G 出现，通常说明岗位在投递时就错配了。最常见于一线执行型岗位（对具体操作直接负责）与候选人策略 / 机制区间错位。模块 A 表一在投递前拦，比在面试里被转推便宜。
