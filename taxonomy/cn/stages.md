# 业务阶段 × 考察重心（cn）

> 模块 A-4 用本表判断业务阶段（依据只能是 [JD]），再结合 `interviewer-types.md` 预判类型。
> "你的对应弹药"列为空，由用户在个人手册或本地副本里填；仓库版永远为空。

| 业务阶段 | 考察重心 | 他要的证据形态 | 常见类型 | 你的对应弹药 |
|---|---|---|---|---|
| **开荒**（0→1） | 框架构建、试错止损、独立作战 | 方案对比 + 假设清单 + 验证路径 + 切换条件 | A | |
| **优化**（成熟期） | 口径严谨、归因、成本结构、上限 | 绝对值 + 折算口径 + 归因分解 | B | |
| **平台**（战略 / 平台期） | 执行层还是机制层、可迁移性 | 机制级证据 | C | |
| **参谋**（战略 / 参谋岗） | 模式梳理、评估与证伪 | 框架 × 指标 × 证伪 | F | |
| **新约束重搭**（换行业 / 换监管） | 能否在新行业新约束下重新搭方案、行业语言差有多大 | 先问现状和禁区 → 分路线框架 → 红线内的动作 | A-2 | |
| **人才分配**（岗位错配时） | 你真正的能力区间在哪、往哪放 | 如实的权限边界 + 清晰的方向陈述 | G | |
| **HR 环节** | 稳定性、动机、定级、到岗 | 可搬运一句话 + 一致口径 | D | |

判断阶段的 JD 线索：
- 开荒：JD 里出现"搭建""从 0""新业务""新渠道"，没有存量指标
- 优化：JD 给出明确的存量指标与提升要求（ROI、成本、转化率）
- 平台：JD 强调"机制""体系""可复用""跨团队"
- 参谋：JD 强调"研究""洞察""评估""汇报"，不直接对业务结果负责
- 新约束重搭：JD 明确要求跨行业背景或标注强监管
- 人才分配：JD 看不出来，只在面试里由类型 G 暴露
