# 通过 / 不通过信号（cn）

> **作者经验规则，命中从零积累。** 来自单一职能小样本，没有统计意义。
> 用法（PROTOCOL B-6）：先逐条填表，再预测。硬信号任一为"是"→ 直接"未通过"；无硬信号时软信号"无法判断"超过一半 → "无法预测"。
> 元规则：**不用表达瑕疵推导结果。** 口头禅、时长、结构松散都不进预测依据。面试官买的是判断结构和信息检索习惯，不是流畅度。
> 表尾的"命中 / 未命中"列供不用个人手册的人本地回填；用手册的人记在手册第 6 节，两处不必同步。

---

## 第一层 · 硬信号（任一出现，预测直接为"未通过"，不再看软信号）

| 编号 | 信号 | 计数口径 | 命中 | 未命中 |
|---|---|---|---|---|
| H1 | 简历与 JD 能力错位 ≥ 2 项 | 模块 A 表一的事后确认；无 JD → 无法判断 | | |
| H2 | 面试官就同一问题反复追问 ≥ 3 轮，候选人始终未答到点上 | 追问 = 面试官换说法再问同一问题；只认转录或笔记计数字段 | | |
| H3 | 候选人对自己简历上的信息答错 ≥ 3 次 | 数字、时间、职责、汇报关系；只认转录或笔记计数字段 | | |
| H4 | 面试官直接质疑简历经历或回答的真实性 | 质疑 = "你确定""这是你做的吗""刚才说 X 现在说 Y"类句式。**出现 1 次 → 结论卡强制附"高危预警"，预测仍走软信号，核心问题排第一；出现 ≥ 2 次 → 硬信号** | | |
| H5 | 实际时长比原定提前 ≥ 1/3 结束 | 原定 / 实际两字段缺任一 → 无法判断 | | |

追问与质疑分开数，不合并。

## 第二层 · 软信号（无硬信号时使用）

左列为通过信号，右列为对应的不通过信号。每一对只看面试官行为，不看态度。

| 通过信号 | 不通过信号 | 命中 | 未命中 |
|---|---|---|---|
| 结尾给"进来后要补什么"的清单 | 结尾给结构性反馈但不提岗位 | | |
| 追简历上与他业务相关的项目 | 只按时间线还原经历，不追项目 | | |
| 主动交底真实业务现状（如流量构成、什么不能做） | 主动介绍公司架构给你"选"（= 当前岗位已否） | | |
| 问 base 地 / 到岗时间 | 问"你想往哪走"（= 在给你换位置） | | |
| 案例题不打断听完 | 案例题中途换题 | | |

## 危害排序口径（写死，模型不得自拍）

触发硬信号 > 触发软不通过信号 > 跨场累计次数 > 离结尾的距离（越近危害越大）。

## 校准提醒

复盘时先填这张表，再下结论。曾有一场瑕疵很多、案例题答偏方向的面试，预测"不过"，实际通过；错在用瑕疵推导结果，没看信号。这是这张表存在的原因。
