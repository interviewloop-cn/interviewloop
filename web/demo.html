下一场，具体改什么？

InterviewLoop 把面前预演、面后复盘和结果回填串成个人手册，让每场面试留下下一次可练的动作。

这个作品探索的是：怎样让 AI 的分析变成用户自己的判断与持续练习。

看产品设计与取舍 ↓看完整输出

已落地：Markdown 协议 · 网页版 · 单文件提示词 · Claude Code skill

一条训练动作怎样产生

从“答得散”，到“学会删掉一条路线”

  1. 记录：案例题讲了三条路线，约四分钟；明知一条与对方现状关系不大，仍讲完了。
  2. 发现：复盘标记“案例失控”。这来自候选人笔记，不能当成面试官的真实评价。
  3. 训练：先确认约束，删掉不适用的路线，练习三分钟收口。
  4. 积累：写入手册，下次检查是否再出现；结果回来后校验原判断。
虚构样本的解释性摘要，非真实用户效果；完整输出及来源见下方。
01 / 产品判断

让训练发生，需要做哪些取舍？

保留人的判断

有些答案，刻意留空

提供应答骨架；只有候选人才能确认的经历、依据和承诺，标成“思考漏洞”，由本人补充。

代价：无法一键完成，用户必须投入思考和练习。

跨场次积累

每次复盘，留下增量

把重复问题、证据口径和新观察写入个人手册，下一场带着已有记录继续训练。

边界：记录不完整或有偏差，分析也会受影响。

让判断可检验

结果出来，再回头核对

先写判断及可能出错的依据，收到真实结果后再回填，保留预测失败的校准记录。

边界：预测不是录用承诺，信号不能证明面试官的真实想法。
